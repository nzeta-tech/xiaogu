# 通用意图路由

普通对话由模型统一判断，不再通过问候、总结、解释、热点或口播句式提前返回执行模式。明确选择的能力、应用参数确认和工作流续接仍沿用已有执行契约。

首页热点入口只传递用户意图、来源、时间和摘要，不指定检索能力。路由使用独立提示，不带预先推断的创作阶段；模型先输出结构化判断：目标、上下文关系、事实依据、资料充分性和是否需要新增外部证据，再输出执行计划。

程序校验判断与计划的一致性。需要证据却直接回答、无需新增证据却启动研究、实质信息任务被归为社交，以及创作缺失研究前置步骤等矛盾，会带具体反馈交给模型重新判断。该校验不按新闻名称或用户关键词选路。已有能力契约校验及异常回退仍保留。

## 验证

- `npm run test:workbuddy-agent` 包含路由一致性与热点入口测试。
- `npm run typecheck` 检查类型。
- `INTENT_EVAL_REPETITIONS=2 node --env-file=.env --experimental-strip-types scripts/eval-workbuddy-intent.mjs` 调用配置的模型运行合成案例，产生模型调用费用，不创建用户任务、不执行应用。

模型评估使用与生产共享的路由提示和输出结构，能力清单为固定测试数据。覆盖同意图不同表达、同表达不同材料充分性、摘要与翻译、跨轮指代、切换话题、稳定知识、社交、来源范围限制、研究后创作及深度研究。结果写入 `artifacts/workbuddy-intent/`。这不代替实际能力检索、模型运行封装、研究工具和完整对话链路的端到端验收，也不证明所有未见表达都能正确识别。

通用语义判断增加了原先直接返回路径的一次模型调用；需在部署后观察路由耗时、重试及误判记录。

本次本地验证：136 项 WorkBuddy 回归测试通过；修订后的 16 个模型评估案例各运行两次，32/32 符合预期。原始首轮为 15/16，失败项是将深度研究报告误判为创作应用，已通过澄清研究产物与创作产物边界修正。评估报告保留原始模型输出，便于后续比较。
