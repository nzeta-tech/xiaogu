# Workbuddy 验收基线

Workbuddy 的验收采用三层证据，不能用单个 Case 或一次人工对话代替整体通过。

## 一键验收

```bash
npm run accept:workbuddy
```

该命令依次执行：

1. Agent Harness、上下文工程、交互协议、应用契约和流量口播回归；
2. localhost 上的真实认证、HTTP、数据库生命周期验收；
3. Next.js 生产构建。

在线验收脚本只允许访问 `localhost`，所有数据库夹具都使用随机 UUID，并在 `finally` 中清理，不产生模型调用或应用扣费。

## 覆盖边界

| 能力域 | 权威证据 |
| --- | --- |
| Agent Loop | observe-decide-act、停止门、语义预算、重复失败熔断、部分成果保留 |
| 多轮上下文 | 主题延续、主题切换、历史投影、Artifact Graph、当前素材与历史成果分离 |
| 应用融合 | 18 条融合链路；研究、文本、图片、视频、PPT、文件、链接、编辑、排队切换 |
| 应用适配 | 26 个目录应用逐个验证输出契约和必填表单；15 个当前开放应用通过在线能力目录核验 |
| 多成果 | 一源一槽、明确数量、缺失槽补偿、两张图片分别下载 |
| Skill 路由 | 显式选择优先；Skill ID 与素材分离；排队切换建立独立新轮和新交付契约 |
| 人工控制 | 交互式应用先确认参数；OpenChatCut 外部写入需要窄范围明确授权 |
| 生命周期 | 认证、列表、详情、文件导入、反馈持久化、成果验收、排队、取消 |
| 可靠性与计费 | 幂等键、取消传播、失败不扣费、运行时账实审计 |
| 展示 | 用户正文与内部过程分离；图片不展开任务信息；每个媒体成果提供独立入口 |

## 运行时审计

```bash
npm run audit:workbuddy -- --since=2026-09-12T00:00:00+08:00
```

运行时审计检查真实任务中的素材丢失、空转、重复调用、缺失成果、取消后扣费和成功结果被失败状态覆盖等问题。历史旧版本任务可按时间窗口隔离，发布验收应使用本次版本上线后的时间点。
