# 固定媒体节点 v1

2026-09-18：候选实现完成，未部署生产。无需 S3/NFS：指定一台现有主机运行独立媒体服务，文件放在持久磁盘，三台 Web 通过内网统一读写。数据库仍只保存归属、对象键、大小和 SHA-256。媒体主机是单点；故障期间媒体上传和读取不可用，普通业务不依赖该服务。

## 请求链路

Agent → 任意 Web 的受鉴权上传接口 → 内网媒体服务 → 持久目录。写入临时文件、计算摘要、完整写盘后原子提交，成功后 Web 登记媒体行。浏览器 → 任意 Web → 校验当前用户归属 → 内网服务流式读取，支持 Range、206 和 416。服务令牌不下发到浏览器或 Agent。

设置 MEDIA_NODE_URL 后，照片、录音、Agent 视频上传和远端视频归档统一使用媒体节点。节点不可用返回错误，不回落到另一台 Web 的本地磁盘。未配置时保留旧存储逻辑，供已有环境兼容；生产三台必须同时配置，禁止混用。已有 database/S3 媒体维持原读取方式。

## 配置与发布顺序

用户已指定 16.176.34.69 为媒体节点（2026-09-18）：EC2 `i-0d5300cf459ede414`，内网 `172.31.20.28`，服务地址 `http://172.31.20.28:3400`，存储集合 ID `xiaogu-media-primary-v1`，规划数据目录 `/data/xiaogu-media`。该选择已写入 env.example；尚未部署或启用，RDS 数据库保持原位置。

1. 在上述媒体主机扩容或挂载持久数据盘。最近核查该节点系统盘只剩约 1.2 GB，不足以长期承载视频。容量按保留天数、每日视频体积及备份规划。数据目录必须在代码发布目录之外。
2. 在主机上用 `findmnt --target /data/xiaogu-media` 验证实际设备与预期数据盘一致；若该目录本身为挂载点，也执行 `mountpoint -q /data/xiaogu-media`。将正确挂载加入启动依赖，挂载失败不得启动服务；Compose 的目录存在检查不等于挂载检查。目录属主应匹配容器 UID/GID，默认 1000:1000。禁止其他服务往对象目录放置符号链接。
3. 将 `scripts/media-node/server.mjs` 放入不可变媒体发布目录。复制 `deploy/media-node/compose.yml` 和 `env.example` 到运维配置目录，将示例保存为 `.env` 并填写真实私网 IP、数据目录、代码目录。另建权限 600 的 `.env.media`，写入随机生成至少 32 字符的 `MEDIA_NODE_TOKEN`，不得入库。
4. 3400 端口仅绑定媒体主机私网 IP；安全组只允许三个 Web 节点访问。不得公开暴露。HTTP 仅用于受控私网；跨公网需 HTTPS 或加密隧道。
5. 在运维目录执行 `docker compose config --quiet` 后 `docker compose up -d`，检查容器健康。健康检查带鉴权，且要求剩余空间大于 512 MiB 保留量加一份 500 MiB 文件。容器重启不会删除挂载文件；健康失败本身不会自动迁移媒体或扩容磁盘。
6. 三台 Web 的容器环境配置相同的 `MEDIA_NODE_URL=http://私网IP:3400`、`MEDIA_NODE_ID=xiaogu-media-primary-v1` 和 `MEDIA_NODE_TOKEN`。仅编辑宿主机 env 文件不足以更新容器，需随候选版本重建并验证。ID 表示存储集合，重启或升级保持不变。
7. 将 `deploy/media-node/media-upload.nginx.conf` 放入每台 Web 的 Xiaogu `server {}` 内。先检查并合并已有同路径 location，避免重复定义。代理 upstream 当前按 127.0.0.1:3001，发布时核对实际端口。每台执行 `nginx -t` 成功后再 reload。
8. 通过正式发布流程进行不可变构建、迁移、候选验收和三节点滚动发布。当前口播生产开关继续保持关闭；本次实现没有打开开关。不能仅替换媒体配置就宣称整组口播功能可上线。

## 限额与错误处理

- Agent 媒体回传路径 `/api/internal/local-agent/digital-human/media` 上限为 500 MiB（524288000 字节），Nginx `500m`、Web、媒体服务一致。其他接口保留原限额；照片和录音原有业务大小限制仍生效。
- 采用单请求流式传输，Nginx 不缓存整个请求体；最长服务请求时间 30 分钟，代理读写空闲超时 30 分钟。本版不支持分片断点续传，连接中断需重新上传。
- 默认最多同时接收 2 个上传。超限返回 503；空间不足 507；超大小 413；鉴权失败 401。应用读取前校验用户归属，其他用户访问返回 404。
- 服务写入临时文件并在关闭时 flush，再以不可覆盖的硬链接提交。正常失败会清理临时文件；进程被强杀可能留下 `.upload-*`，仅在停止上传并确认无写入时清理。
- 如果对象已上传但数据库写入报错，保留对象：数据库错误可能发生在提交成功后，直接删除可能破坏已登记媒体。定期离线对照数据库引用审计孤儿文件，保留恢复窗口后再清理；本版不自动删除用户文件。重复成片更新也可能留下旧对象。

## 存量迁移、备份与回退

启用前重新盘点 digital_human_media_assets 中 local_disk 记录（此前生产核查为 0）。有存量时，暂停相关写入、备份数据库和文件，按 storage_key 汇集文件，核对文件大小和摘要，验证读取后再将对应 storage_node_id 改为 MEDIA_NODE_ID。只改节点 ID 或只同步数据库均不安全。不匹配的旧节点记录会明确报迁移错误，避免误读另一块磁盘。

公共照片发布包继续按 `SPOKEN_RELEASE_READINESS.md` 接入各 Web 的只读 runtime；媒体服务不自动导入公共模板。模板声音及禅境语音合成已整体下线，不再发布声音模板包。个人资产要同时迁移媒体文件、媒体行和资产行，不能只同步模板包。

为数据盘建立定期备份/快照，并记录与数据库备份相匹配的恢复点；上线前验证恢复。回退媒体服务代码时保留数据盘和 ID。产生新节点媒体后不能直接回退到不认识媒体节点的 Web 代码，否则新文件无法读取；应保持兼容读取版本或先完成数据迁移。节点故障无自动主从切换。
