# 定位选题优化 · 第二版

本次只修改本地代码，未发布，也未修改用户记忆或生产数据。

## 当前策略

保留“5个素材题＋1个个人定位题”。第六题优先体现创作者如何理解当前素材，不要求引用客户案例或出现具体品牌。

- 长期身份、受众、专业能力与历史案例分开。画像人设不再拼入个人故事锚点，故事记忆也不直接作为定位。
- 历史案例是可选参考：重复片段只算一次，仅选择能解释本轮问题的真实片段。没有相关案例时，仅用专业视角即可。
- 完全取消最近10轮历史查询、历史选题提示词和跨轮重复判定。生成过不等于选过或发布过；重复测试或持续讨论同一主题不需要声明“继续深挖”，也不必强求新方向。
- 只保留当轮六个候选的区分检查，避免同一批提供多个实质相同的选项。
- 检查第六题是否贴合素材、是否有真实定位依据、是否硬带品牌。不合格时仅重写第六题一次，再复核。仍不合格则明确报错，不交付占位题或虚假通过结果。
- 没有有效个人定位时，允许素材中立题，不编造能力或经历。相关素材可以正常讨论泰康，不设品牌黑名单。

领域判断只看本轮素材。`topicProcess.version` 更新为8，保留 `positioningReview` 状态，沿用已有持久化路径，无需数据库迁移。

## 边界

案例筛选与语义质检仍依赖模型。筛选不可用时不带入历史案例；质检不可用时不能声称通过。新增模型调用的耗时仍存在，但已移除历史查询及其失败依赖，不再向模型提供最近10轮的选题上下文。

发布验收补充：结构化选题与复核使用流式传输来避免上游网关等待完整 JSON 导致的 524；仅收到完整结束标记后返回文本，截断和错误事件不能被当作成功。GPT 结构化任务使用 low 推理强度，模型与审核规则不变。
